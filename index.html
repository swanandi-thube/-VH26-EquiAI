Multi-Factor Decision Engine & Scoring Lab

Interactive mathematical model calculating object value scores across 8 normalized dimensions.

Mathematical Formulation Normalized Multi-Factor Scoring
Object Value Score =
  + (Wf × Frequency Score) + (Wr × Recency Score) + (Wp × Popularity Score)
  + (Wc × Retrieval Cost) + (Wfresh × Freshness) + (Wt × Trend Score)
  + (Wv × Reuse Probability) - (Ws × Size Penalty)
All individual factor scores are normalized to [0.0, 1.0]. Weights adapt dynamically when switching between Read-Heavy API (prioritizes frequency & popularity) and Compute-Heavy Recommendation (prioritizes recomputation cost & reuse probability).
RETAIN
Assigned when composite Score ≥ 0.40 and object is fresh. Value derived from high frequency or expensive retrieval outweighs memory footprint.
REFRESH
Assigned when Score ≥ 0.45 but object age reaches ≥ 75% of TTL. Background pre-fetch is dispatched asynchronously before miss occurs.
EVICT
Assigned when Score < 0.40 or low reuse probability makes the object a poor use of cache capacity under memory pressure.

Cache Strategy Battle: Smart Cache vs LRU vs LFU vs GDS

Side-by-side object-level decision comparison showing how each algorithm evaluates identical resident items.

LRU (Least Recently Used)
Optimizes solely for recency. Vulnerable to one-hit-wonder scans and evicts expensive-to-compute cold items prematurely.
LFU (Least Frequently Used)
Optimizes solely for historical hit count. Suffers from cache pollution from stale legacy objects with high historical counts.
GDS (Greedy Dual-Size)
Optimizes for Cost/Size ratio with inflation clock L. Misses dynamic traffic trends and temporal freshness constraints.
Smart Cache (Adaptive)
Holistically balances Frequency, Recency, Size, DB Latency, Staleness, and Trend with dynamic TTL recalibration.

Why a Hybrid Adaptive Heuristic Model?
A fully black-box ML model (e.g. reinforcement learning or deep neural networks) requires large offline production datasets, introduces non-deterministic inference latency overhead (5-15ms) on the cache lookup critical path, and lacks explainability for system operators.

This prototype utilizes an adaptive, multi-factor heuristic model with runtime weight adaptation. This guarantees sub-millisecond execution, complete mathematical explainability, and deterministic behavior across arbitrary traffic patterns.
Key Innovations vs LRU / LFU / GDS
  • Application-Aware: Adapts factor weights for Read-Heavy vs Compute-Heavy workloads.
  • Dynamic TTL: Extends TTL on surging hot items; shrinks TTL on volatile mutating items.
  • Proactive Background Refresh: Refreshes high-value expiring objects before users suffer miss latency penalties.
  • Pollution Defense: Detects single-use crawler floods and shields core resident memory.
  • Cost-Benefit Scaling: Scales cache capacity only when expected DB savings exceed memory costs.
